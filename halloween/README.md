# «Погладь котика» — хелоуїнський розіграш HRme School

Людина лишає контакти, гладить чорного котика й отримує один із 7 подарунків.
Кожен бере участь лише один раз, усі дані потрапляють у Google Таблицю.

- **Сторінка** — файли в цій папці, живе на GitHub Pages за адресою https://halloween.hrme.site
- **Сервер** — Google Apps Script (`apps-script/Code.gs`), прив'язаний до Google Таблиці.
- **Сховище** — Google Таблиця з аркушами «Учасники» і «Налаштування».

Подарунок обирає **лише сервер**. На сторінці немає ні списку призів, ні ваг, тому
оновлення сторінки чи режим інкогніто не допоможуть «перетягнути» приз.

## Що де лежить

| Файл | Навіщо |
| --- | --- |
| `index.html` | Сама сторінка (і котик, намальований у SVG) |
| `style.css` | Оформлення та анімації |
| `app.js` | Логіка: форма, гладження, показ подарунка |
| `texts.js` | **Усі тексти сторінки** — правте тут |
| `config.js` | Адреса вебзастосунку Apps Script |
| `assets/` | Долоня, павутинка, зірки, котик, іконка, картинка для прев'ю, звук муркотіння `purr.mp3` |
| `CNAME` | Адреса сайту для GitHub: `halloween.hrme.site` |
| `apps-script/Code.gs` | Код сервера (на сайті не працює, лежить тут для зручності) |
| `apps-script/appsscript.json` | Налаштування проєкту Apps Script (для довідки) |

## Запуск: крок за кроком

> Google може показувати меню англійською або українською — залежно від мови акаунта.
> Нижче назви кнопок англійською (як у ТЗ), у дужках — український варіант.

### Крок 1. Таблиця і скрипт

1. Створіть нову Google Таблицю (https://sheets.new). Назвіть її, наприклад, «Хелоуїн — котик».
2. У меню таблиці: **Розширення → Apps Script** (Extensions → Apps Script).
3. Відкриється редактор із файлом `Code.gs`. Видаліть усе, що там є, і вставте весь
   вміст файлу `apps-script/Code.gs` з цього репозиторію. Натисніть 💾 **Save** (Зберегти).
4. Ліворуч натисніть ⚙️ **Project Settings** (Налаштування проєкту) →
   **Time zone** (Часовий пояс) → оберіть **(GMT+02:00) Kyiv** / Europe/Kyiv.
5. Поверніться до редактора (значок `< >` ліворуч). У списку функцій зверху оберіть
   **setup** і натисніть ▶ **Run** (Виконати).
6. Google попросить дозвіл: **Review permissions** → оберіть свій акаунт →
   **Advanced** (Додатково) → **Go to … (unsafe)** (Перейти до …) → **Allow** (Дозволити).
   Це нормально: скрипт ваш, і він працює лише з цією таблицею.
7. У таблиці з'являться аркуші **«Учасники»** і **«Налаштування»**. Готово.

### Крок 2. Публікація вебзастосунку

1. У редакторі Apps Script справа вгорі: **Deploy → New deployment**
   (Розгорнути → Нове розгортання).
2. Біля «Select type» натисніть ⚙️ і оберіть **Web app** (Вебзастосунок).
3. Заповніть:
   - **Description** — будь-що, наприклад «котик»;
   - **Execute as** — **Me** (Я);
   - **Who has access** — **Anyone** (Усі).
4. Натисніть **Deploy** (Розгорнути). Скопіюйте **Web app URL** — адресу, що закінчується на `/exec`.
5. Відкрийте файл `config.js` і вставте адресу між лапками замість `PASTE_WEB_APP_URL_HERE`:
   ```js
   API_URL: 'https://script.google.com/macros/s/AKfycb…/exec'
   ```
6. Перевірка: відкрийте цю адресу в браузері. Якщо бачите `{"status":"ok",…}` — сервер працює.

### Крок 3. Завантажити файли на GitHub

1. На https://github.com натисніть **+** → **New repository**.
   Назва — будь-яка (наприклад, `halloween`), тип — **Public**, натисніть **Create repository**.
2. На сторінці репозиторію: **Add file → Upload files**.
3. Перетягніть **вміст** цієї папки (не саму папку): `index.html`, `style.css`, `app.js`,
   `texts.js`, `config.js`, `CNAME`, `README.md`, папки `assets` і `apps-script`.
   Файли мають лежати в корені репозиторію, а не всередині ще однієї папки.
4. Внизу натисніть **Commit changes**.

### Крок 4. Увімкнути GitHub Pages

1. У репозиторії: **Settings → Pages**.
2. **Source**: **Deploy from a branch**.
3. **Branch**: `main`, папка `/ (root)` → **Save**.

### Крок 5. Свій домен

1. Там само, у **Settings → Pages**, поле **Custom domain**: впишіть `halloween.hrme.site` → **Save**.
   (Файл `CNAME` уже містить цю адресу, тож поле, найімовірніше, заповниться саме.)

### Крок 6. DNS у «Хостинг Україна»

1. Увійдіть у панель «Хостинг Україна» → **Домени** → `hrme.site` → **DNS-зона** (керування DNS).
2. Додайте запис:
   - **Тип**: `CNAME`
   - **Ім'я** (піддомен): `halloween`
   - **Значення**: `<ваш-логін-на-GitHub>.github.io` (наприклад, `olha-hrme.github.io`)
3. Збережіть. Основний сайт hrme.site цей запис не зачіпає.
4. Оновлення DNS займає від кількох хвилин до кількох годин.

### Крок 7. HTTPS

Коли GitHub перевірить домен (у **Settings → Pages** з'явиться зелена галочка
«DNS check successful»), поставте галочку **Enforce HTTPS**. Якщо вона неактивна — зачекайте
ще трохи, GitHub видає сертифікат до 24 годин.

## Якщо змінили `Code.gs`

Після будь-якої зміни коду скрипта треба оновити вебзастосунок, **не створюючи новий**
(інакше зміниться адреса):

**Deploy → Manage deployments** (Керувати розгортаннями) → оберіть розгортання →
✏️ **Edit** (Редагувати) → **Version**: **New version** (Нова версія) → **Deploy**.

Адреса залишиться тією самою, `config.js` міняти не потрібно.

> Зміни на аркуші «Налаштування» (призи, ваги, дати) оновлювати так **не треба** —
> скрипт читає їх щоразу заново.

## Як керувати розіграшем

### Аркуш «Налаштування»

Ліворуч — таблиця призів:

| Колонка | Що означає |
| --- | --- |
| **ID** | Службова назва. Не змінюйте для призів, які вже видавали |
| **Великий напис** | Те, що буде великими літерами на сувої |
| **Підпис** | Рядок під ним |
| **Вага** | Шанс випадіння. 30 і 10 означають «у 3 рази частіше». 0 — не випадає |
| **Активний** | `так` / `ні`. Неактивний приз не випадає |

Зараз ваги 30 + 30 для знижок і 10 × 4 для уроків, тобто приблизно 60% знижок і 40% уроків.

Праворуч (колонки H–J) — параметри:

| Параметр | Значення | Що означає |
| --- | --- | --- |
| `lucky_number` | 77 | Учасник під цим номером отримує «Золотого котика» (консультацію) |
| `end_date` | 31.10.2026 23:59 | Після цього часу (Київ) нові люди бачать «Розіграш завершено» |
| `consultation_given` | ні | Сервер сам ставить «так», коли видасть консультацію |

Консультація ніколи не випадає випадково: її отримує лише учасник із номером `lucky_number`,
і тільки якщо `consultation_given` = «ні». Вагу консультації можна не чіпати.

Усе це можна змінювати просто під час розіграшу — нові учасники одразу отримають нові налаштування.
Ті, хто вже брав участь, при повторному візиті бачать свій приз з актуальним текстом із «Налаштувань».

### Аркуш «Учасники»

Кожен рядок — одна людина: номер, час, email, телефон (як ввели і нормалізований), канал,
приз, «Забрав» (так/ні), коли натиснули «Отримати подарунок», токен.
Новий рядок з'являється лише для нового email **і** нового телефону.

Після «Отримати подарунок» у колонці «Забрав» з'являється «так» — далі ви пишете людині вручну.

### Перевірити розподіл призів: `simulate()`

У редакторі Apps Script оберіть у списку функцію **simulate** → ▶ **Run**. Внизу відкриється
**Execution log** (Журнал виконання): скільки разів із 200 випав кожен приз і скільки разом
знижок та уроків. Нічого не записується в «Учасники».

## Як правити тексти

Усі тексти сторінки — у файлі `texts.js`. На GitHub: відкрийте файл → ✏️ (Edit this file) →
змініть текст **лише між лапками** → **Commit changes**. Сайт оновиться приблизно за 1–10 хвилин.

Винятки:
- **Тексти подарунків** — на аркуші «Налаштування» в таблиці, не в `texts.js`.
- **Заголовок і опис для прев'ю** в Telegram/Facebook — у самому верху `index.html`
  (рядки `og:title` та `og:description`): месенджери не запускають скрипти, тому ці тексти мають
  бути прямо в HTML.

Якщо виправили щось, а сайт показує стару версію — відкрийте його в режимі інкогніто.

**Звук муркотіння** — файл `assets/purr.mp3` (зараз 4 секунди, 42 КБ), грає по колу, поки котика гладять.
Щоб замінити, завантажте новий MP3 з тією самою назвою: моно, 2–5 секунд, до 100 КБ.

## Чекліст перевірки перед запуском

Тестуйте на справжній сторінці з вашими тестовими email і телефонами.

- [ ] **Форма не відправляється** з неправильним email, телефоном, без вибору каналу чи без згоди —
      під полем з'являється підказка.
- [ ] **Новий учасник** — у «Учасниках» новий рядок з номером, подарунком і токеном.
- [ ] **Той самий email з іншим телефоном (і навпаки)** — показується той самий подарунок
      з написом «Ви вже гладили котика!», нового рядка немає.
- [ ] **Після оновлення сторінки** людина одразу бачить свій подарунок.
- [ ] **«Отримати подарунок»** — з'являється поп-ап, у таблиці «Забрав» = так і час.
- [ ] **Консультація**: поставте `lucky_number` = 3, пройдіть розіграш трьома різними тестовими
      контактами — «Золотий котик!» має випасти саме третьому і більше нікому.
- [ ] **`simulate()`** — у журналі близько 60% знижок і 40% уроків.
- [ ] **Два одночасні запити не отримують однаковий номер.** Відкрийте сторінку, натисніть F12 →
      вкладка **Console**, вставте й натисніть Enter:
      ```js
      const send = (i) => fetch(CONFIG.API_URL, { method: 'POST',
        headers: { 'Content-Type': 'text/plain;charset=utf-8' },
        body: JSON.stringify({ action: 'draw', email: 'race' + i + '@example.com',
          phone: '+38050000000' + i, channel: 'email', consent: true, hp: '' }) }).then(r => r.json());
      Promise.all([send(1), send(2), send(3)]).then(console.log);
      ```
      У «Учасниках» з'являться три рядки з різними номерами підряд.
- [ ] **Гладження мишкою і пальцем**: iPhone Safari, Android Chrome, а також відкрийте посилання
      всередині Telegram, Instagram і Facebook. Якщо погладити не виходить, за 6 секунд з'являється
      кнопка «Не виходить погладити? Натисніть тут».
- [ ] **Після `end_date`** — тимчасово поставте дату в минулому й перевірте з новим email:
      має з'явитися «Котик пішов спати». Потім поверніть 31.10.2026 23:59.
- [ ] **https://halloween.hrme.site** відкривається з замочком (HTTPS), а прев'ю в Telegram показує
      картинку з котиком. Якщо Telegram показує старе прев'ю — надішліть посилання боту
      [@WebpageBot](https://t.me/WebpageBot); для Facebook —
      [Sharing Debugger](https://developers.facebook.com/tools/debug/) → **Scrape Again**.
- [ ] **Перед запуском**: видаліть тестові рядки в «Учасниках» (усі, крім заголовка),
      поверніть `lucky_number` = 77 і `consultation_given` = ні.

> Щоб у своєму браузері знову побачити форму після тестів, відкрийте сайт в інкогніто
> або очистіть дані сайту — сторінка пам'ятає вашу участь.

## Часті питання

**Людина каже, що бачить «Котик відволікся».** Це помилка мережі або сервера. Дані у формі
зберігаються, можна натиснути ще раз. Якщо так у всіх — перевірте адресу в `config.js` і що
вебзастосунок опублікований з доступом **Anyone**.

**Номери учасників збилися після видалення рядків.** Номер нового учасника = кількість заповнених
рядків у «Учасниках» + 1. Тому тестові рядки треба видалити **до** запуску, а під час розіграшу
рядки краще не видаляти.

**Хтось повернувся після 31.10.** Нові люди бачать «Розіграш завершено», а ті, хто вже брав участь,
і далі бачать свій подарунок і можуть натиснути «Отримати подарунок».

**Бот заповнив форму.** На сторінці є приховане поле-пастка. Якщо воно заповнене, сервер відповідає
як зазвичай, але нічого не записує в таблицю.
